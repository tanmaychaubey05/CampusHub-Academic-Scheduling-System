2. Introduction

Peer tutoring and self-organized study sessions are cornerstones of collegiate academic success. When classmates collaborate on algorithmic puzzles, systems programming labs, or database designs, their understanding and course grades improve dramatically.

However, running study circles over WhatsApp or Discord is notoriously frustrating. Meeting timings get lost in conversational clutter, peer mentors double-book review slots, and shared study materials get buried or expire. CampusHub is an academic platform written in pure Python that brings order to student collaboration through course-indexed study groups, conflict-free scheduling, categorized resource indexing, attendance analytics, and an integrated academic integrity engine.

3. Problem Statement

College students face clear, recurring obstacles when attempting to organize study groups:

  • Cluttered Communication: Meeting details and locations disappear under hundreds of chat messages.
  • Double-Booking: Tutors handling multiple subjects frequently schedule conflicting study slots on the same day.
  • Unindexed Study Materials: Notes, past paper solutions, and code files are scattered across personal cloud links that get lost.
  • Zero Accountability: No record exists of who attended review meets or whether the tutor's explanations were clear.
  • Academic Integrity Risks: Collaborative groups need tools to ensure shared materials are original rather than plagiarized or synthetic code.

4. Functional Requirements

Module 1: User & Study Group Management

  • User Authentication: Secure student and tutor sign-up with email validation, password checks, and salted PBKDF2 SHA-256 hashing.
  • Course Study Groups: Creation of subject cohorts (e.g. CSE2001) with capacity controls.
  • Approval Workflows: Direct enrollment for public groups and leader authorization queues for private groups.

Module 2: Session Scheduler & Conflict Detector

  • Conflict-Free Booking: Review session scheduling with room locations or virtual video links.
  • Algorithmic Interval Collision Check: Mathematical detection preventing overlapping bookings: (StartA < EndB) AND (EndA > StartB).
  • RSVP & Verified Attendance: Seat reservation and timestamped check-in attendance verification.

Academic Resource Repository Submodule

  • Categorization: Notes, Past Papers, Code Scripts, Slides, and Reference Guides.
  • Tag Indexing & Multi-Search: Fast filtering by keyword, course code, and comma-separated tags.
  • Download Frequency Auditing: Dynamic counter tracking material popularity.

Module 3: Peer Review & Analytics Engine

  • 5-Star Review System: Attendees rate sessions and provide written feedback; hosts are prevented from self-rating.
  • Turnout Ratios: Automated computation of attendance percentage: (Verified / Total RSVPs) * 100%.
  • Performance Dossiers: Auto-generated academic performance reports for cohorts.

Academic Integrity & AI Code Detection Module

  • Plagiarism Comparison Engine: Token winnowing algorithm to compute Jaccard similarity and containment percentages.
  • AI Code Detector: Calculates Shannon token entropy, Type-Token Ratio, line length burstiness variance, and checks for AI boilerplate.

5. Non-Functional Requirements

  • Performance: Sub-50ms query latency via database indexes on session times, courses, and usernames. SQLite Write-Ahead Logging (WAL) enabled.
  • Security: Salted PBKDF2 SHA-256 password hashing (100,000 rounds) and parameterized SQL queries to prevent SQL injection.
  • Zero-Dependency Execution: Runs natively on Python 3 standard library with zero external pip package installation overhead.
  • Reliability: ACID transactional integrity with automated rollback upon operational exceptions.
  • Maintainability: Clean layered Service-Model-Repository architecture across 13 distinct Python modules.

8. Design Decisions & Rationale

  • Standard Library Focus: Eliminates installation barriers so evaluators can run the project on any standard Python setup.
  • Interval Collision Logic: Prevents scheduling clashes algorithmically at insertion time, providing 100% schedule reliability.
  • MOSS-Style Winnowing for Plagiarism: Fingerprints token streams so comparisons remain robust against superficial variable renaming.

9. Implementation Details

The codebase is organized into modular Python files:

  • campushub/models/: Defines data transfer classes (User, StudyGroup, StudySession, StudyResource, SessionReview).
  • campushub/services/: Implements business logic (AuthService, GroupService, SchedulerService, ResourceService, AnalyticsService, IntegrityService).
  • campushub/database/: Provides connection handling, schema definition, and ACID transactions.
  • campushub/cli/: Formats clean terminal menus and tables.
  • campushub/web/: Provides zero-dependency HTTP server with JSON REST APIs and frontend dashboard.

12. Challenges Faced

  • Interval Collision Edge Cases: Solved by using universal overlap logic: (StartA < EndB) AND (EndA > StartB).
  • In-Memory Database Persistence during Tests: Retained persistent connection pointers during unit test executions.
  • Zero-Dependency Browser GUI: Implemented using native http.server and Vanilla JS.
